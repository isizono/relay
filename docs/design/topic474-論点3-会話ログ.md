### T2 — ユーザー

### T3 — ユーザー
> substrate Aダッシュってそもそもなんだっけ。わいはメモリの中身分からんぞ

**アシスタント（要旨）**: A'（Aダッシュ）は**この会話で自分が作った造語**でメモリには無い、と謝って整理。
- 案A（正規）= relay disk ゼロ、保証は送信側 e2e ack → 監査が「構造的に不可」
- 案B = relay が disk buffer を持つ → 監査の優位案
- 案C = 外部 broker(NATS) → スケール過剰で脱落
- A'（造語）= disk ゼロだが保証を購読者 pull に置く変種。案A の死因を回避するが、flaky な pull に依存する弱点あり。

### T4 — ユーザー
> メッセージの保持は、LMDBにする話なかったっけ？ちょっと調べて。
> で下は、あれ？場history の retentionがメッセージの保持だっけ？ちょっと待って頭こんがらがってきたから、一回現在の場所をおさらいしてもらえる？優しめにね

**アシスタント（要旨）**: cc-memory 検索で裏取り。
- **LMDB は決定事項ではない**。監査内で「案B の engine 候補」として比較されただけ。決まっているのは SQLite（D#2260 移行 / D#2283 msg_id 採番、outbox も SQLite 前提）。LMDB は「SQLite が詰まったら検討」の保留。
- こんがらがりの正体＝**3つの軸を混同**:
  - 軸1 engine（どこに置く）= SQLite 現役 / LMDB 将来候補
  - 軸2 何を保持（2種類ある）= outbox（配達中の荷物, 24h）と 場 history（過去ログ, 90日）← 監査の最重要発見「2機構混同」
  - 軸3 retention（どれだけ持つ）= 上記の各期間
- 現在地: 決まり=L#3135/L#3137。未決=論点#3（substrate A 系 vs B、場 history retention）。

### T5 — ユーザー
> アウトボックスは持つとして、Bで。
> ログを持たないことは正しいか？困るケースある？転送するだけなら既にサービスはありそう？
> あと、身分データとかは？意外とこれも一時的に持つ必要はあるのか？

**アシスタント（要旨）**: **substrate = B 確定**（ユーザー裁定）。3問に回答:
- **Q1 ログ持たないは正しい**: 場 history を読む候補は SSE resume（outbox がカバー）と backscroll（L#3135 で非ケース）だけ。困るのはライブデバッグ便宜のみ → observability で代替。長期 archive は実消費者ゼロ。
- **Q2 既存サービス**: YES、それが案C（NATS）だった。規模過剰で棄却済み。broker を入れても固有グルー（label-subset fan-out / 3系統 seq / ow lease / cc-memory 協調）は自分で書く。relay は「SQLite+SSE の上の薄い ~300行アダプタ」でフルスクラッチ broker ではない。
- **Q3 身分データ**: presence/subscription/lease/identity は全部 liveness=自己修復。re-subscribe + heartbeat で再構築されるので **disk 不要、RAM には持つが永続化しない**。**disk が要るのは outbox だけ**。

### T6 — ユーザー
> 場ヒストリーはなしにしようか。

**アシスタント（要旨）**: 場 history **完全廃止**で確定。永続性が outbox 1本に畳まれ、監査 発見1 の「2機構混同」が解消。at-least-once は outbox だけで閉じるので配達保証は 1ミリも弱らない。手放すのはライブデバッグ便宜のみ。後始末リスト（FR-1.1/1.4/1.5 削除）を提示し、FR-1.4 `since=N` を「完全削除 or outbox ドレインに読み替え」どちらかを質問。

### T8 — ユーザー
> あでもサーバーログはとるでいいかも？リレーのデバッグ用に。90日で消える

**アシスタント（要旨）**: 「データとしての場 history」と「relay 自身のデバッグ用サーバーログ」は別物、と区別。
- サーバーログ＝**sink に徹する**（append-only / payload 込み / 90日 TTL / 購読者向けエンドポイントなし）。`since=N` を生やすと裏口から場 history 復活なので禁止。FR-8 observability の領分、outbox の SQLite とは物理分離。
- さまよっていた「90日」がここで本当の住処を得た（場 archive 90日からの移設）。
FR-1.4 の読み替え/削除を再度質問。

### T9 — ユーザー
> その心は？ただきいてみただけ

**アシスタント（要旨）**: 聞かれて考え直し、**自己訂正**:
- `since=N` は「N より後ろを再生できる台帳」があって初めて意味を持つ。その台帳＝場 history を消した以上、引く先が無い。
- resume は「購読者が seq 申告」ではなく「**relay が当該購読の未 ack outbox を黙って再 push**」。relay 側 ack 状態がカーソルそのもの。
- → 自分の「読み替え」推しが甘かった。**完全削除が正しい**に倒れた。since は将来の重複抑制ヒントとして optional 余地のみ。
